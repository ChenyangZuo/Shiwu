# 时物 App · 第三阶段开发计划（多清单）

> 状态：已完成 · 2026-08-01（真机验证通过：新建/切换/删除清单，首页/愿望单联动）

## 一、需求理解

当前应用只有一份物品清单（首页标题固定为「我的物品」）。本阶段目标是支持**维护多份物品清单**：

- 首页标题展示当前清单名，**点击标题可切换清单**；
- 每一份清单都是完整的「物品 + 心愿单」集合：切换清单后，首页、愿望单页、统计页内容同步切换；
- 各页面的新增操作归属到当前清单。

## 二、现状

- `ShiwuRepository`：单例 + StateFlow，JSON 文件持久化（`items / wishes / categories / nextItemId / nextWishId`）；
- 五个 Tab（首页/愿望/统计/我的）+ 覆盖层（详情/表单/回收站/分类/主题）；`ShiwuApp` 统一收集 `items`、`wishes` 传给各页面；
- 数据模型：`Item`、`Wish` 均无清单维度，全局一份。

## 三、数据模型变更

1. 新增清单实体 `InventoryList`（避免与 `kotlin.collections.List` 冲突）：
   - `id: Long`、`name: String`、`createdAt/updatedAt`
2. `Item`、`Wish` 增加字段 `listId: Long`（默认归属默认清单）。
3. 存储文件增加 `lists` 数组与 `nextListId`；`currentListId` 存入 SharedPreferences（跨重启记住当前清单）。
4. **迁移**：读取旧 JSON 时若没有 `lists` 字段，自动创建默认清单「我的物品」，并把已有物品/心愿全部归属到它，重启不丢数据。

## 四、界面交互

- 首页 `AppHeader` 标题改为当前清单名 + 下拉指示，点击弹出**清单切换面板**（底部滑入，复用现有覆盖层动画风格）：
  - 清单列表：名称 + 统计（物品 n · 心愿 m）+ 当前清单选中态；
  - 操作：新建清单、重命名、删除（二次确认）；
  - 切换后首页/愿望单/统计实时刷新，空清单显示空状态。
- 愿望单页、统计页的数据按当前清单过滤；新增物品/心愿归属当前清单。
