## 一、目标

把第一版的静态界面（假数据、无交互）升级为「可真实使用」的版本：

- 所有输入框可点击并唤起输入法，按钮点击有实际效果；
- 物品/愿望单支持真正的增删改查（CRUD）；
- 数据真实持久化，重启 App 不丢失；
- 首页总览、统计页数据由真实数据实时计算；
- 个人页的导入导出、备份、回收站、设置变为可用。

## 二、现状

- Jetpack Compose（Material3）+ 单 Activity；五屏 + 物品详情页 + 心愿表单 + 回收站；
- 数据层已落地：`ShiwuRepository`（单例 + StateFlow）+ JSON 文件持久化（`filesDir/shiwu_data.json`），首次启动写入种子数据；
- 交互已打通：搜索/键盘、增删改查、退役/复役、心愿转物品、回收站、导入导出、备份、统计实时计算；
- 覆盖层统一动画：详情/表单/回收站从底部滑入滑出；详情→编辑为直接切换。

## 三、技术方案（含实际落地说明）

| 主题 | 方案 | 说明 |
| --- | --- | --- |
| 状态管理 | App 级 Repository 单例 + Kotlin StateFlow | 已落地 |
| 数据持久化 | **JSON 文件存储（实际采用）** | 原计划 Room，但 AGP 9 内置 Kotlin 与 kapt/KSP 均不兼容，且 kapt 所需编译组件下载被网络 TLS 拦截；按计划兜底为 `org.json` 文件存储，Repository 接口独立，后续可平滑替换为 Room |
| 输入/键盘 | `adjustResize` + `imePadding` | 已落地，真机验证输入法可唤起 |
| 日期选择 | Material3 `DatePickerDialog` | 已落地（表单购入日期、退役日期） |
| 照片 | 相册 Photo Picker + 拍照（FileProvider） | 已实现，**拍照/相册待真机确认** |
| 导航 | 当前 Tab + 覆盖层方案 | 详情/表单/回收站均为覆盖层，返回手势按优先级逐层关闭 |
| 删除 | 软删除进回收站 | 已落地；**30 天自动清理逻辑待做** |
| 交互路径 | 点卡片 → 详情页 → 编辑表单 | 详情页提供退役/复役、编辑、删除；从详情进入编辑直接显示（不滑入），返回回到详情页 |

### 补充需求（已并入各阶段）

1. **首页顶栏搜索图标**：已移除（保留下方搜索栏与分享按钮）。
2. **心愿单录入表单与物品表单差异**：已核实设计稿无心愿表单示意；心愿表单为独立字段（名称/分类/预计价格/优先级/已攒金额/备注），不含照片/购入日期/日均成本。已落地。
3. **退役功能**：已落地 —— `Item.retired` + `retirementDate`；日均成本规则（使用中 = 价格÷持有天数，已退役 = 价格÷服役天数）；详情页退役（日期选择）/复役；首页三档过滤（全部/使用中/已退役）。
